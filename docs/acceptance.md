# Acceptance and evidence

Run `bash scripts/integration.sh` for real PostgreSQL/Redis/MinIO/Mailpit tests and `bash scripts/acceptance.sh` for the pinned full stack. Both scripts require Docker Compose v2, Node 22 and pnpm 10.32.1. Install Playwright Chromium with `pnpm exec playwright install chromium`. On this Mac, the installed Chrome can be selected with `E2E_BROWSER_CHANNEL=chrome`. Full acceptance needs the loopback ports in Compose to be free and enough memory/disk for Flare, Novu, MongoDB, PostgreSQL, Postal/MariaDB, Redis, and source-built MinIO. No external provider credentials are required for the local simulation.

The full-stack script copies source into a new private temporary directory, generates independent credentials/certificates, starts an isolated Compose project, and removes its containers, volumes and files on exit. It never uses the existing checkout's `.env`, certificates or data volumes. It applies current migrations and separately upgrades a disposable database from the committed `62aaa57` migrations, checking existing workflow content survives. It seeds twice, configures the pinned Novu owner/environments through its real API, and creates Flare integrations. Generated private files, browser traces and raw provider logs are not uploaded as CI artifacts. On failure, only bounded, filtered error lines with credentials and opaque values redacted are printed.

A private authoritative CoreDNS zone publishes the actual generated DKIM/SPF/MX records. Flare's normal verification poller resolves them through `DOMAIN_DNS_SERVERS`; no test marks domains verified directly. This certifies resolver/parsing/polling behavior against local DNS, not public DNS propagation, provider ownership or email deliverability. The override accepts only operator-configured resolver IPs and must never derive from an API request.

The scenarios exercise real Flare HTTP authentication, real Novu workflow acceptance, locale fallback, pinned content publication/reconciliation, preferences, Novu → SMTP AUTH/STARTTLS → Flare → Mailpit, Bcc hiding, DKIM source, suppression and inbound persistence/retrieval. Postal-shaped inbound callbacks are signed using a locally generated RSA key; those are simulated submissions. Delivery events injected by the test are explicitly tagged `acceptance-simulated-delivery`, not represented as real provider confirmations. Browser tests cover login/workflow, domain/email, inbound sandbox/source download, layout publication and safe dead-letter redrive.

The load stage stops the worker, submits at the default 10 requests/second plus a simultaneous 40-request burst, checks throttling headers and repeated idempotency keys, then deletes only the disposable Redis database and restarts the worker. It requires all accepted logical messages to reach Mailpit with exactly one transport attempt and no duplicate database operation. API/worker RSS is sampled against a configurable `ACCEPTANCE_MEMORY_MAX_BYTES` ceiling (768 MiB default). This is a bounded reproducible smoke load, not a maximum throughput benchmark or production sizing guarantee.

## Completion ledger

Do not call acceptance complete unless every required row has evidence for the candidate commit.

The script includes native Inbox delivery/read-state and a sixth live browser flow, delay/digest/throttle/HTTP execution, local MFA enrollment and concurrent replay rejection, and a final isolated multi-store restore drill. Independent action/browser/restore groups report combined failures while preserving a failing exit status. The restore runs after load recovery, stops the disposable producers, and compares restored PostgreSQL security/data, native Novu mappings, Postal databases, Redis canaries and object bytes/metadata without starting sending workers. See [deployment restore instructions](deployment.md).

[CI run 38538818077](https://github.com/ChariPramod/flare/actions/runs/38538818077) passed all three jobs on `7d91b54` on 2026-10-14. It verified 137 unit/database tests, 11 browser contract flows, 12 real-service tests, package installation, and the expanded pinned-stack script with all six live browser flows. Native Inbox/actions and local MFA checks passed. The load stage accepted 54 distinct messages, observed 30 expected throttles and sampled peak API RSS of 185,323,520 bytes. All accepted messages recovered after Redis loss with exactly one provider attempt and no duplicate logical submission. Worker RSS remained below the configured 768 MiB ceiling. The isolated restore completed in 44 seconds for the synthetic fixture.

The staging-preparation candidate `daa76f7` passed four jobs in [CI 38543738466](https://github.com/ChariPramod/flare/actions/runs/38543738466): standard checks (143 unit/database tests, 25 deterministic evals, 11 browser contracts and package installation), all 12 integration tests, synthetic Compose/Caddy configuration validation, and the expanded full-stack acceptance with all six live browser flows. Load accepted 54 logical sends with 30 expected throttles and 188,473,344 bytes peak API RSS; queue-loss recovery lost no accepted sends and duplicated no logical/provider submissions. The isolated restore passed in 38 seconds.
