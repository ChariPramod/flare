# Historical documents

These files preserve the project's earlier intent and checkpoint evidence. They are useful for tracing decisions, but are not current deployment instructions or a claim that every original requirement has been verified.

| Record                                                        | Purpose                                                                                              |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [Original build brief](build-spec.md)                         | The initial product scope, research context and requested implementation phases                      |
| [Progress through 2026-10-19](progress-through-2026-10-19.md) | Earlier checkpoint descriptions, verification results and limitations retained from the progress log |

Start with [current progress](../../PROGRESS.md) for the active checkpoint, [plans](../planning/README.md) for upcoming work, and [acceptance evidence](../development/acceptance.md) for verification boundaries. A historical statement that a dependency was unavailable or a check was pending describes that checkpoint only; consult newer evidence before drawing a current conclusion.

Preserve historical evidence when shortening active status documents. Add dated context or a link to a superseding record instead of silently changing an old outcome.
